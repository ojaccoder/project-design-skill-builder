# 从安装到第一次改版

## 1. 安装生成器

准备 Node.js 22.20 或更新版本，在项目目录运行：

```bash
npx skills add ojaccoder/project-design-skill-builder
```

按提示选择使用的编程助手。默认只安装到当前项目；需要跨项目使用时加 `-g`。如果助手暂未识别，重新开启项目会话。

也可以下载 GitHub 仓库，将 `skills/project-design-skill-builder` 整个文件夹交给助手，要求它按所在工具的 Skill 目录规范安装。保留 `references/`，已有同名 Skill 时先检查版本，避免重复安装。

## 2. 提供项目背景

在助手里打开项目，然后发送：

```text
使用 project-design-skill-builder 分析这个项目。
先问我影响设计的关键背景问题，再生成一套项目专属的设计 Skill。
优先核心任务和必要状态，区分产品底线、方案选择与可选建议。
图片和动效按需要使用，保留必要说明。
```

它先检查现有代码、组件和素材，再判断项目更接近 Operate（工具/工作台）、Persuade（官网/落地页）、Read（文档/知识库）还是 Experience（作品集/展览）。然后询问缺失的信息，例如目标用户、核心任务、参考偏好、设备与业务约束。已有答案不必重复提供；可以直接补充你不喜欢的页面和具体原因。

## 3. 看清交付内容

项目专属 Skill 会记录：

- **项目背景**：谁使用、主要任务、需要保留的业务内容。
- **产品模式**：当前页面优先服务完成任务、理解价值、阅读内容还是沉浸体验。
- **视觉与文案**：布局层级、配色、字体、间距，以及哪些解释应该删除。
- **约束层级**：产品底线、本次方案选择、可选建议；明确适用页面与调整条件。
- **图片与动效（按需）**：使用理由、图片主题、动画反馈及降级方式；不需要时可省略。
- **验收方式**：桌面与手机截图、键盘操作、状态反馈；需要时补充录屏。

这些是保存在项目里的文件。生成完成后，让助手告诉你文件路径，确认方向再用于实现。

## 4. 按规则改页面

```text
按刚生成的项目设计 Skill 改造当前页面。
验证主要任务、状态和目标设备上的体验；需要图片或动效时再加入。
```

后续新增页面也可以要求沿用同一份 Skill。产品目标或设计方向改变时，同步修改规则。

## 图片、动效和模型

项目需要图片或动效时，生成的规范才会说明其用途和行为。生图调用助手已有的图片能力；动效优先使用项目现有依赖或浏览器原生 API。环境缺少模型或浏览器能力时，助手应说明限制，不能把提示词当成已生成的图片，也不能把概念图当成真实页面。

官网的三步表单只是本地模板演示。它不会读取你的仓库或调用在线模型；完整分析与生成在编程助手中进行。

## 更新

```bash
npx skills check
npx skills update
```

`check` 检查已安装 Skill，`update` 按 CLI 的提示更新。保留自己修改过的项目专属规则，避免将它与通用生成器混淆。
